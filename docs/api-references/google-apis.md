## 2. Auth: service account JWT with impersonation (`subject`)

Verified against `google-auth-library` source: `JWTOptions` includes `subject?: string` — "The impersonated account's email address". `GoogleAuth` accepts `clientOptions` which are passed to the constructed auth client, so `clientOptions: { subject }` also works.

**Critical DWD facts:**
- The token is minted per-`subject`. **One JWT client == one impersonated user.** To read N partners' data, construct N clients (they're cheap; token fetch happens lazily and is cached per client until expiry, default 1h).
- For Gmail calls, `userId` must be `'me'` (or exactly the impersonated email). Passing a *different* user's email as `userId` yields **403 "Delegation denied for <email>"**.
- The service account itself needs **no IAM roles** for this; authorization comes entirely from the Admin console DWD grant. The GCP project must have **Calendar API and Gmail API enabled**.

```typescript
import { google, calendar_v3, gmail_v1 } from 'googleapis';
import { JWT } from 'google-auth-library';

const SCOPES = [
  'https://www.googleapis.com/auth/calendar.readonly',
  'https://www.googleapis.com/auth/gmail.readonly',
];

// Option A — explicit JWT client (recommended for DWD: subject is first-class)
export function delegatedClientsFor(userEmail: string): {
  calendar: calendar_v3.Calendar;
  gmail: gmail_v1.Gmail;
} {
  const auth = new JWT({
    // from the downloaded service-account key JSON:
    email: creds.client_email,
    key: creds.private_key,        // keep the literal \n newlines intact
    scopes: SCOPES,                // must be a subset of the Admin-console grant
    subject: userEmail,            // the Workspace user to impersonate
  });
  return {
    calendar: google.calendar({ version: 'v3', auth }),
    gmail: google.gmail({ version: 'v1', auth }),
  };
}

// Option B — GoogleAuth with keyFile (uses clientOptions.subject)
const auth = new google.auth.GoogleAuth({
  keyFile: '/path/to/sa-key.json',   // or GOOGLE_APPLICATION_CREDENTIALS
  scopes: SCOPES,
  clientOptions: { subject: 'partner@yourdomain.com' },
});
const calendar = google.calendar({ version: 'v3', auth });
```

Notes:
- `creds` = `JSON.parse(fs.readFileSync(keyPath, 'utf8'))` or env-injected; fields used: `client_email`, `private_key`. If the key transits an env var, restore newlines: `private_key.replace(/\\n/g, '\n')`.
- You can also set auth globally: `google.options({ auth })` — avoid with multi-user impersonation; pass auth per-service instance instead.
- `new JWT(...)` per user per process is fine; each caches its own access token.

## 3. Admin console: authorize domain-wide delegation

Done once by a **super administrator** of the Workspace domain (verified against Google's service-account OAuth doc, current path):

1. GCP console: create the service account, create a JSON key. Note the **Client ID** — the long **numeric** ID (also `client_id` in the key JSON). Enable **Google Calendar API** and **Gmail API** on the project.
2. Google Admin console (admin.google.com): **Main menu > Security > Access and data control > API Controls**.
3. In the **Domain wide delegation** pane, click **Manage Domain Wide Delegation**.
4. Click **Add new**.
5. **Client ID** field: paste the service account's **numeric client ID** (NOT the `...@...iam.gserviceaccount.com` email — using the email is a documented cause of `unauthorized_client`).
6. **OAuth scopes** field: comma-delimited list, exactly:
   `https://www.googleapis.com/auth/calendar.readonly,https://www.googleapis.com/auth/gmail.readonly`
7. Click **Authorize**.

Propagation: "usually a few minutes… in some cases up to 24 hours." Scopes requested at token time must be a subset of scopes granted here — a mismatch produces `unauthorized_client` at the token endpoint.

## 4. Calendar: today's events for a user

### Endpoint

`GET https://www.googleapis.com/calendar/v3/calendars/{calendarId}/events`
(calendarId = `'primary'` for the impersonated user's main calendar.)

Scopes accepted (any one): `calendar`, `calendar.readonly`, `calendar.events`, `calendar.events.readonly`.

### Parameter semantics (important, verified)

- `timeMin` — **lower bound (exclusive) on the event's END time**, RFC3339 with mandatory offset (`2026-08-05T00:00:00-07:00` or `...Z`).
- `timeMax` — **upper bound (exclusive) on the event's START time**.
  ⇒ Together they return every event that *overlaps* the window (incl. multi-day events in progress).
- `singleEvents: true` — expands recurring events into instances. **Required for `orderBy: 'startTime'`** (startTime ordering is only valid on single events; otherwise the API 400s).
- `orderBy` — `'startTime'` (asc) or `'updated'` (asc). No descending option.
- `maxResults` — default 250, max **2500** per page; paginate via `nextPageToken`.
- `eventTypes` — repeatable filter; allowed values: `birthday`, `default`, `focusTime`, `fromGmail`, `outOfOffice`, `workingLocation`. Simplest server-side filter for a meetings tool: `eventTypes: ['default']`.
- `showDeleted` (default false), `timeZone` (response TZ; defaults to calendar's), `q` (free-text over summary/description/location/attendee names+emails).

```typescript
function todayWindow(tz: string): { timeMin: string; timeMax: string } {
  // Build day bounds in the user's TZ; toISOString() (UTC Z-form) is valid RFC3339.
  const now = new Date();
  const start = new Date(now.toLocaleString('en-US', { timeZone: tz }));
  start.setHours(0, 0, 0, 0);
  const offsetMs = now.getTime() - new Date(now.toLocaleString('en-US', { timeZone: tz })).getTime();
  const timeMin = new Date(start.getTime() + offsetMs);
  const timeMax = new Date(timeMin.getTime() + 24 * 3600 * 1000);
  return { timeMin: timeMin.toISOString(), timeMax: timeMax.toISOString() };
}

const { data } = await calendar.events.list({
  calendarId: 'primary',
  timeMin, timeMax,                 // RFC3339 strings
  singleEvents: true,
  orderBy: 'startTime',
  maxResults: 2500,
  eventTypes: ['default'],          // skip OOO/focus/workingLocation/birthday/fromGmail
});
const events = data.items ?? [];    // calendar_v3.Schema$Event[]
// data.nextPageToken for pagination; data.nextSyncToken only when no time filters used
```

### Event resource — fields you'll use

```jsonc
{
  "id": "abc123",                       // opaque; instance ids look like "<parentId>_20260805T170000Z"
  "status": "confirmed" | "tentative" | "cancelled",
  "eventType": "default",               // default | outOfOffice | focusTime | workingLocation | birthday | fromGmail
  "summary": "Title",
  "description": "may contain HTML",
  "location": "free-form text",
  "start": { "dateTime": "2026-08-05T10:00:00-07:00", "timeZone": "America/Los_Angeles" },
  "end":   { "dateTime": "..." },       // ALL-DAY events use {"date": "2026-08-05"} instead of dateTime
  "recurringEventId": "parentId",       // present on expanded instances (singleEvents=true)
  "originalStartTime": { "dateTime": "..." },
  "organizer": { "email": "...", "displayName": "...", "self": true? },
  "attendees": [
    {
      "email": "a@x.com",               // only guaranteed-ish field
      "displayName": "Ada",             // often absent
      "responseStatus": "needsAction" | "declined" | "tentative" | "accepted",
      "organizer": true?,               // boolean, present when true
      "self": true?,                    // this attendee == the calendar being read
      "resource": true?,                // meeting rooms/resources — filter these out of people lists
      "optional": true?,
      "additionalGuests": 0
    }
  ],
  "hangoutLink": "https://meet.google.com/xxx-yyyy-zzz",   // convenience link when Meet attached
  "conferenceData": {
    "conferenceId": "xxx-yyyy-zzz",
    "conferenceSolution": { "key": { "type": "hangoutsMeet" }, "name": "Google Meet" },
    "entryPoints": [
      { "entryPointType": "video", "uri": "https://meet.google.com/...", "label": "..." },
      { "entryPointType": "phone", "uri": "tel:+1...", "pin": "..." }
      // types: video | phone | sip | more
    ]
  },
  "visibility": "default" | "public" | "private" | "confidential",
  "transparency": "opaque" | "transparent",   // transparent = shows as Free
  "attachments": [ { "fileUrl": "...", "title": "...", "mimeType": "..." } ]
}
```

**Filtering guidance for a "partner meetings" tool:**
- Keep `eventType === 'default'` only (or use the `eventTypes` request param). `outOfOffice`, `workingLocation`, `focusTime` are personal-status events; `birthday` and `fromGmail` are noise. `fromGmail` events are read-only Gmail imports (flights, reservations).
- No `attendees` array at all usually means a solo/self event.
- Skip attendees with `resource: true` (rooms) when listing people. Note: for events on someone else's calendar you're not an attendee of, attendee lists may be truncated or absent depending on visibility.
- Consider skipping events where the `self` attendee has `responseStatus === 'declined'`, and events with `transparency === 'transparent'`.
- All-day events have `start.date`/`end.date` (no `dateTime`); guard for both shapes.

## 5. Gmail: threads, search, headers

### threads.list

`GET https://gmail.googleapis.com/gmail/v1/users/{userId}/threads` — `userId: 'me'` (mandatory-in-practice under DWD).

Params: `q` (Gmail search-box syntax), `maxResults` (default 100, **max 500**), `pageToken`, `labelIds[]` (AND semantics), `includeSpamTrash`. `q` is not usable with the `gmail.metadata` scope (fine — you're on `gmail.readonly`).

Response:
```jsonc
{
  "threads": [ { "id": "18f...", "snippet": "latest msg preview", "historyId": "..." } ],
  "nextPageToken": "...",
  "resultSizeEstimate": 42          // ESTIMATE only — do not trust for counting
}
```

### Search syntax (`q`) — verified specifics

- Domain correspondence: `q: '{from:acme.com to:acme.com cc:acme.com}'` — `{a b c}` is Gmail's OR form; `from:acme.com OR to:acme.com` also works. `from:`/`to:` match on domain suffix.
- Dates: `after:2026/08/01 before:2026/08/05` (YYYY/MM/DD). **Interpreted as midnight PST/PT** — for timezone accuracy the API accepts **epoch seconds**: `after:1754377200 before:1754463600`. Also `older_than:1y`, `newer_than:2d`.
- Others: `has:attachment`, `in:anywhere` (includes Spam/Trash), `in:sent`, `deliveredto:x@y.com`, `-from:me` (negation).
- API vs UI differences (documented): the API does **not** expand account aliases, and it matches **individual messages**, not whole threads, when evaluating `q` (a thread is returned if *any* message matches).

### threads.get

`GET https://gmail.googleapis.com/gmail/v1/users/{userId}/threads/{id}`

| `format` | Returns | Use when |
|---|---|---|
| `minimal` | message ids, labelIds only | existence checks |
| `metadata` | ids, labels, **headers only** (restrict with `metadataHeaders[]`) | subject/date/participants — cheapest useful option |
| `full` | everything incl. parsed body `payload` + parts | need bodies/attachments |

```typescript
const { data: thread } = await gmail.users.threads.get({
  userId: 'me',
  id: threadId,
  format: 'metadata',
  metadataHeaders: ['Subject', 'From', 'To', 'Cc', 'Date'],  // repeatable param
});

// thread.messages: gmail_v1.Schema$Message[] — each:
// { id, threadId, labelIds[], snippet, internalDate /* epoch MS as string */,
//   payload: { headers: [{name, value}], mimeType, parts?, body? }, sizeEstimate }

const h = (msg: gmail_v1.Schema$Message, name: string) =>
  msg.payload?.headers?.find(x => x.name?.toLowerCase() === name.toLowerCase())?.value ?? '';

const first = thread.messages![0];                    // messages are in thread order, oldest first
const subject = h(first, 'Subject');
const dateMs  = Number(first.internalDate);           // prefer internalDate over Date header (spoofable/absent)
const participants = ['From', 'To', 'Cc'].flatMap(n =>
  h(first, n).split(',').map(s => s.trim()).filter(Boolean));
```

Header parsing: `From`/`To`/`Cc` values are RFC5322 (`"Name" <a@b.com>, c@d.com`); use a real parser (e.g. `email-addresses` npm) rather than regex if display names matter. Header name matching must be case-insensitive.

### Finding the EARLIEST thread with a domain — efficiently

There is **no ascending sort**: list results come back newest-first (widely observed; ordering is UNVERIFIED in official docs — do not hard-depend on it). Options, cheapest first:

1. **Binary search on time using epoch-second `before:`** (recommended; O(log years) list calls at 5–10 units each):

```typescript
async function earliestThreadWithDomain(gmail: gmail_v1.Gmail, domain: string) {
  const base = `{from:${domain} to:${domain} cc:${domain}}`;
  const any = async (q: string) =>
    (await gmail.users.threads.list({ userId: 'me', q, maxResults: 1 })).data.threads?.length ? true : false;

  if (!(await any(base))) return null;
  // binary search the earliest epoch second S such that mail exists before S+1
  let lo = Date.UTC(2004, 3, 1) / 1000 | 0;         // Gmail launch, safe floor
  let hi = Math.floor(Date.now() / 1000);
  while (lo < hi) {
    const mid = Math.floor((lo + hi) / 2);
    (await any(`${base} before:${mid}`)) ? (hi = mid) : (lo = mid + 1);
  }
  // everything in [lo-1day, lo+1day] to be safe around boundary semantics
  const { data } = await gmail.users.threads.list({
    userId: 'me', q: `${base} after:${lo - 86400} before:${lo + 86400}`, maxResults: 100,
  });
  // resolve exact earliest by internalDate of first message of each candidate
  let best: { id: string; ms: number } | null = null;
  for (const t of data.threads ?? []) {
    const { data: th } = await gmail.users.threads.get({
      userId: 'me', id: t.id!, format: 'metadata', metadataHeaders: ['Subject', 'From', 'Date'],
    });
    const ms = Number(th.messages?.[0]?.internalDate ?? Infinity);
    if (!best || ms < best.ms) best = { id: t.id!, ms };
  }
  return best;
}
```

2. **Paginate to the last page** of `threads.list` (500/page) and take the final item — simple, correct-enough, but costs 10 units/page and relies on the unofficial newest-first ordering.
3. `messages.list` variant of (1) is cheaper per call (5 units vs 10) and `internalDate` then comes straight from `messages.get` — use if you want the earliest *message* rather than thread.

## 6. Attachments

### Identifying attachments in a payload (format=full)

`payload` is a MIME tree: `multipart/*` parts have `parts[]`; walk recursively. An attachment part has a non-empty `filename`, and either:
- `body.attachmentId` (+ `body.size`) — content stored separately, fetch via attachments.get (normal case), or
- `body.data` inline (small parts) — already base64url.

```typescript
interface FoundAttachment { filename: string; mimeType: string; attachmentId?: string; inlineData?: string; size: number; }

function findAttachments(part: gmail_v1.Schema$MessagePart | undefined, out: FoundAttachment[] = []): FoundAttachment[] {
  if (!part) return out;
  if (part.filename && (part.body?.attachmentId || part.body?.data)) {
    out.push({
      filename: part.filename,
      mimeType: part.mimeType ?? 'application/octet-stream',
      attachmentId: part.body.attachmentId ?? undefined,
      inlineData: part.body.data ?? undefined,
      size: part.body.size ?? 0,
    });
  }
  for (const p of part.parts ?? []) findAttachments(p, out);
  return out;
}
```

### attachments.get

`GET https://gmail.googleapis.com/gmail/v1/users/{userId}/messages/{messageId}/attachments/{id}`
→ `MessagePartBody`: `{ attachmentId?, size, data }` — `data` is **base64url** (`-`/`_` alphabet, may lack padding).

```typescript
const { data: body } = await gmail.users.messages.attachments.get({
  userId: 'me',
  messageId: msg.id!,
  id: att.attachmentId!,
});
const bytes = Buffer.from(body.data!, 'base64url');   // Node ≥15.7 handles base64url natively
// fallback: Buffer.from(data.replace(/-/g,'+').replace(/_/g,'/'), 'base64')
```

The same base64url decoding applies to inline `body.data` on message parts (e.g. text/html bodies). Note: `attachmentId` values are not stable long-term identifiers; fetch them within the same session as the message read (stability is UNVERIFIED in docs — don't persist them as durable keys).

## 7. Quotas, rate limits, batching (verified live 2026-08)

### Calendar API
- **10,000 requests/min per project**; **600 requests/min per user per project** (requests, not units).
- Exceeding → `403` or `429` with `usageLimits`/`rateLimitExceeded` reasons. Handle with truncated exponential backoff (1s → 2s → 4s… cap ~32–64s, ±random jitter up to 1s).
- No documented daily cap.

### Gmail API (units changed vs. older docs — these are the current numbers)
- **1,200,000 quota units/min per project**; **6,000 quota units/min per user per project** (older docs said 15,000/min/user — the current page says 6,000); **80,000,000 units/day per project** — a *daily billing threshold* that per docs **cannot be increased**.
- Per-method costs (current, live-verified — several went UP vs historical values):
  | method | units |
  |---|---|
  | `messages.list` | 5 |
  | `threads.list` | 10 |
  | `messages.get` | 20 (was 5 historically) |
  | `attachments.get` | 20 (was 5) |
  | `threads.get` | 40 (was 10) |
  | `messages.send` | 100 |
- Budget example: scanning one user = 10 (threads.list) + 40 × threads fetched. 6,000 units/min/user ⇒ ~150 `threads.get`/min per impersonated user. Note the per-user bucket keys on the **impersonated** user, so fanning out across many partners multiplies your effective throughput up to the project cap.
- 429 also triggers on per-user concurrent request limits and bandwidth limits.

### Batch requests (2026 status)
- Still supported, **no deprecation notice** on either API's batch guide. Homogeneous batches only (one API per batch), `multipart/mixed`, **max 100 inner calls, ≤50 recommended** (larger batches trigger rate limiting). Inner calls each count fully against quota — batching saves HTTP overhead, not quota.
- Endpoints (from live discovery docs): Gmail `https://gmail.googleapis.com/batch`; Calendar `https://www.googleapis.com/batch/calendar/v3`. (The Gmail guide page still shows the older `/batch/gmail/v1` path form — the discovery doc's `rootUrl+batchPath` above is authoritative.)
- **The Node `googleapis` client has no batch helper** — no `batch` method is exposed; you must hand-build the multipart/mixed request (or just use `Promise.all` with a concurrency limiter, which the library's HTTP/2 mode handles well: `google.options({ http2: true })` is available). For this tool's volumes, plain concurrent requests + backoff are simpler and sufficient.

## 8. Error semantics

Error shape (both APIs, thrown by googleapis as `GaxiosError` — inspect `err.response?.status`, `err.response?.data?.error`, and `err.errors`):

```jsonc
{ "error": { "code": 403, "message": "...", "errors": [ { "domain": "global", "reason": "rateLimitExceeded", "message": "..." } ] } }
```

Token-endpoint errors (thrown during the first API call, when the JWT is exchanged) instead look like OAuth errors: `err.response.data = { error: 'invalid_grant', error_description: '...' }`.

### DWD-specific failures

| Symptom | Cause | Fix |
|---|---|---|
| `unauthorized_client` ("Client is unauthorized to retrieve access tokens using this method") at token exchange | Client ID not registered in Admin console DWD; OR registered by **email instead of numeric client ID**; OR requested scope not in the granted scope list | Register numeric client ID with exact scopes; wait for propagation (minutes → 24h) |
| `invalid_grant` ("Invalid email or User ID") | `subject` user doesn't exist in the domain (typo, offboarded) | Validate the email against your directory first |
| `invalid_grant` ("Invalid JWT: Token must be a short-lived token… clock skew") | Server clock skew, or stale `iat`/`exp` | Sync NTP; library computes claims itself, so skew is the usual culprit |
| `invalid_grant` (other) | Suspended user; deleted/disabled service-account key; key revoked | Check user status and key validity |
| **403 `Delegation denied for user@x.com`** (Gmail API, after auth succeeds) | Gmail call made with a `userId` different from the impersonated `subject` | Always pass `userId: 'me'`; make a new client per subject |
| 400 `failedPrecondition` / "Mail service not enabled" | Impersonated user has no Gmail license (e.g. Cloud Identity-only) — commonly observed wording; exact reason string UNVERIFIED in docs | Skip non-Gmail users |
| 403 `domainPolicy` | Workspace admin has disabled API access to Gmail for that OU | Admin console app-access settings |
| 404 (Gmail `users.*`) | Bad `messageId`/`threadId`/`attachmentId`, or message deleted | Treat as gone; 404 on the *user* itself usually surfaces as `invalid_grant`/400 at auth instead |
| 404 (Calendar) | `calendarId` not found / not visible to the impersonated user | Use `'primary'` under impersonation |
| 403/429 `rateLimitExceeded`, `userRateLimitExceeded`, `dailyLimitExceeded` | See quotas above | Truncated exponential backoff w/ jitter; treat 403-with-rate-reason same as 429 |
| 401 `authError` | Token expired/invalid mid-flight | The JWT client auto-refreshes; persistent 401 ⇒ scope/key problem |
| 500/502/503/504 `backendError` | Google-side | Retry with backoff (min ~1s initial) |

Backoff sketch:

```typescript
async function withBackoff<T>(fn: () => Promise<T>, max = 6): Promise<T> {
  for (let i = 0; ; i++) {
    try { return await fn(); } catch (e: any) {
      const s = e?.response?.status ?? e?.code;
      const reason = e?.response?.data?.error?.errors?.[0]?.reason ?? '';
      const retriable = s === 429 || s >= 500 ||
        (s === 403 && /rateLimitExceeded|userRateLimitExceeded|usageLimits/.test(reason));
      if (!retriable || i >= max) throw e;
      await new Promise(r => setTimeout(r, Math.min(64_000, 2 ** i * 1000) + Math.random() * 1000));
    }
  }
}
```
